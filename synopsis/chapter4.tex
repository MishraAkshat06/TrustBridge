\chapter{Scope of the Project}

TrustBridge is scoped as an academic MVP (Minimum Viable Product) and research prototype targeting the Ethereum Sepolia testnet. The scope is defined along three dimensions: the proposed system architecture, what the system will include, and what it explicitly excludes.

\section{Proposed System Architecture}

TrustBridge is organised as a five-layer architecture in which the advisory intelligence layer and the financial-control layer are deliberately kept separate. The Application Layer (Flask + scikit-learn + Agentic AI) computes risk and success signals but never holds funds or private keys, while the Smart Contract Layer holds all contributor funds in escrow and executes only predefined, human-authorised release rules. The separation of concerns is the key design principle: advisory intelligence informs human decisions, and only a smart contract --- triggered by an authorised human verifier --- moves money.

\section{In Scope}

\begin{itemize}
    \item A fully functional web application with nine frontend pages: Home/Explore, Campaign Details, Create Campaign, Creator Dashboard, Contributor Dashboard, Milestone/Evidence, Wallet, AI Risk Assessment, and Transaction History.
    \item A Python Flask backend exposing REST APIs for campaign metadata, ML prediction, anomaly scoring, Agentic AI analysis, and KYC status.
    \item A scikit-learn ML pipeline trained on a publicly available historical crowdfunding dataset (e.g., Kickstarter data from Kaggle), evaluated across three model families.
    \item An Isolation Forest anomaly detection module returning a risk signal per campaign.
    \item Four Agentic AI agents implemented in Python using an LLM API (NVIDIA Nemotron or equivalent), returning structured JSON outputs.
    \item A mock KYC module that simulates identity verification without storing real identity documents.
    \item A Solidity smart contract deployed to the Ethereum Sepolia testnet enforcing: hard cap (20 ETH), escrow, four-tranche milestone release, partial refunds, and access control.
    \item MetaMask wallet integration via Ethers.js v6.
    \item End-to-end testing covering at least 50 transactions on Sepolia, with all results auditable on Etherscan.
    \item A research paper draft structured for potential submission to an academic venue.
\end{itemize}

\section{Out of Scope}

\begin{itemize}
    \item Production-scale deployment or mainnet Ethereum usage.
    \item Guaranteed fraud prevention or investment advice.
    \item Storage of real KYC documents (Aadhaar, PAN) on-chain or in any database.
    \item Automatic physical-world milestone verification without human involvement.
    \item Direct LLM control of financial transactions or private-key management.
    \item Support for blockchains other than Ethereum Sepolia.
    \item Legal compliance for a production crowdfunding product.
\end{itemize}

\section{System Boundary}

The system boundary of TrustBridge encompasses: (a) the React frontend running in the contributor/creator browser; (b) the Flask backend and ML pipeline running on a local or cloud server; (c) the Agentic AI agents calling an external LLM API; (d) the Solidity smart contract running on the Sepolia testnet; and (e) the off-chain SQLite database storing campaign metadata, KYC status, and AI analysis outputs. The blockchain itself and the MetaMask wallet are external dependencies outside the system boundary.
